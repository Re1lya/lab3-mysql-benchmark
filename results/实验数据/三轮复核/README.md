# 三轮复核数据

本目录保存 2026-10-18 已完成、2026-10-23 从 CDWY3 只读取回的同批实验原始记录。没有重新运行压力测试，也没有替换或修剪高延迟样本。

- 服务器来源：`/root/lab3-results/supplement-20261018`。
- 54 组，93600 次请求；每个配置 r1、r2、r3 各一轮。
- 读取 1000/1050/1100/1150/1200 线程，10 秒升压，2 次循环；写入 1000/1100/1200/1300 线程，10 秒升压，1 次循环。JPA 与 MyBatis 各一套。
- 每组保留原样的 `samples.jtl`、`jmeter.log`、`console.log`、`start.txt`、`end.txt`。
- 第一轮 18 份 JTL 与原提交目录中的 JTL 的 SHA-256 逐一匹配。原有第一轮文件、图表和监控不替换。
- 复核发现 54 组均无既定断言失败；49 组满足“成功且 elapsed≤40ms 的比例≥80%”的本组比较条件。它不代表指导书强制的验收标准。
- MyBatis 1300 线程写入 r1/r2/r3 平均耗时为 102.03/6.76/6.05 ms；JPA 为 3232.80/13.30/8.12 ms。不能据第一轮宣称固定性能上限。
- 后两轮没有随本批取回每组完整监控与数据库基线快照，不能据 JTL 单独证明各轮预热、缓存、数据恢复、其他进程负载全部一致，也不能把第一轮监控图片作为第二、三轮监控。

## 复算

在仓库根目录执行：

```bash
python3 deploy/lab3/analyze-three-rounds.py
```

只读取本地归档并重算统计，不访问服务器、不启动应用或 JMeter。输出 `统计结果.json`、`三轮逐组统计.csv` 和 `SHA256清单.json`。P95/P99 使用排序样本的线性插值；吞吐量使用首个请求开始至最后请求结束的时长；`peak_threads` 是 JTL 采样时记录的 `allThreads` 最大值，不等同于配置线程数或瞬时在途请求数。

`deploy/lab3/analyze-final.py` 仍只复核原提交的第一轮 18 组。两个统计范围不可混用。
